Compiler: GNU Fortran (GCC) 17.0.0 20260510 (experimental), Windows.
External transform reference: SciPy 1.15.3. Frequency edge references use
mpmath at 100 decimal digits.

All 5,743 native checks passed in both checked (`-O0`) and optimized (`-O3`)
builds with runtime checks and traps for invalid arithmetic, division by zero,

## Native checks

Create `build\fft-native` before running:

```cmd
gfortran -O0 -g -fcheck=all -ffpe-trap=invalid,zero,overflow -fbacktrace -Werror=implicit-interface -Jbuild\fft-native -Ibuild\fft-native -Ibuild\gfortran_2806A042DAA8BBF7 src\fft.f90 test\test_fft.f90 build\gfortran_3C159EB802C22FB9\scifort\libscifort.a -o build\fft-native\test_fft.exe
build\fft-native\test_fft.exe
```

The optimized native command substitutes `-O3` for `-O0` and
`fft-optimized` for `fft-native`, retaining runtime checks, arithmetic traps,
and implicit-interface errors. FPM directory hashes are local artifacts;
use matching module/archive paths from the local build.

The tests independently evaluate the DFT and cosine/sine defining matrices,
and check inverse pairs, all normalization and endpoint-weight settings,
orthonormal energy, real/complex agreement, noncontiguous inputs, input
preservation, padding/cropping, odd/even Hermitian endpoints, frequencies,
shifts, empty/singleton cases, nonfinite inputs, invalid options, and
extension integer-range rejection. DFT lengths cover 1-33; direct
cosine/sine matrices cover lengths 1-12, with DCT-I requiring length > 1.

## External references

```cmd
python validation\check_fft.py --module-dir build\gfortran_2806A042DAA8BBF7 --library build\gfortran_3C159EB802C22FB9\scifort\libscifort.a
```

The script uses NumPy RNG seed 20261112 and checks 5,302 cases. Transform
lengths include smooth and prime sizes through 1009. Cases include real
and complex inputs, shorter/longer/empty inputs with explicit length,
all four cosine/sine types, all three normalizations, default and explicit
orthogonalization, odd/even half sequences, bin spacings of both signs,
large and small spacing, shifts, and amplitudes `1e-100` and `1e100`.
It compiles `src/fft.f90` and the input-driven validation driver explicitly;
the archive supplies unchanged dependencies. Driver input is outside `test/`
and does not add keyboard input to unattended FPM tests.

Reference build flags are `-O0 -g -fcheck=all
-ffpe-trap=invalid,zero,overflow -fbacktrace` and `-O3 -fcheck=bounds`.
Errors are maximum complex absolute errors divided by the larger of the
maximum input magnitude, maximum reference magnitude, and minimum normal
binary64 value. The acceptance bound is `2e-12`. This preserves meaningful
relative checks for the `1e-100` cases instead of using a unit absolute floor.

SciPy 1.15.3's complex DCT/DST implementation omits the `orthogonalize`
argument when it calls its backend. The checker instead applies the public
real transform separately to each complex component with that option intact.
Frequency references use mpmath when forming `n*d` would overflow in the
tested SciPy/NumPy helper. These deliberate compatibility differences are
also documented in the [FFT guide](../docs/fft.md).

## Scope and limits

The module covers rank-one binary64 transforms and reuses the existing
mixed-radix/Bluestein FFT engine. Symmetric DCT/DST embeddings need up to
`8*n` complex entries. Binary64 intermediate range and rounding limits
apply. Inputs must be finite; rejected calls return empty arrays and status.
Multidimensional and axis-based APIs, fast Hankel transforms, fast-length
helpers, workers, backend controls, and overwrite options remain open.
No dependency, imported implementation, or C ABI symbol was added.
