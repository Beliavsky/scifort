# Larger AAA spectrum validation

Date: 2026-11-13. Compiler: GNU Fortran (GCC) 17.0.0 20260510
(experimental), Windows. Numerical reference: SciPy 1.15.3 and analytic
secular-polynomial roots.

## Change and scope

AAA's pole, zero, residue, and cleanup methods now use an internal normalized
arrowhead QZ backend through 512 retained support points. It adapts
Reference-LAPACK v3.12.1's `ZHGEQZ` and supporting kernels, reusing SciFort's
existing Hessenberg reducer. The similarities fix coordinate one and commute
with the second pencil factor `diag(0,I)`, so that factor remains unchanged.
No linked LAPACK/BLAS dependency is needed.

An explicit logical mask tracks finite projective roots. This avoids using
NaN sentinels in the root array; the existing optimized regression is checked
with invalid-operation, division-by-zero, and overflow traps enabled.

The existing general-purpose QZ, generalized-eigenvalue, matrix-function,
Hessenberg, and SVD numerical implementations were not changed. The isolated
change affects AAA spectra and their cleanup callers, with umbrella integration
covered by native tests. No build configuration or dependency declaration
changed. The full SciFort suite also passed with `fpm test` (exit status 0),
as required by the instructions supplied for this task. FPM rebuilt its stale
cached objects and executables before running the suite. The run emitted
array-temporary runtime warnings but no test failures.

## Native and existing reference tests

Three focused programs passed in debug and optimized builds, both with bounds/
runtime checks, floating-point exception traps, and implicit-interface errors:

- `test_interpolate_aaa`: 170 checks, including the updated 41-support regression
  whose spectra and automatic/manual cleanup previously returned status 4.
  Existing analytic rational cases, small spectra, extreme scaling, and cleanup
  behavior remain covered.
- `test_interpolate_aaa_large`: 89 checks for larger real and complex fits,
  poles, zeros, residues, manual/automatic cleanup, actual pole removal,
  support accounting, analytic roots, homogeneous infinite eigenvalues, shape
  and finite-input checks, and the resource guard before solver allocation.
- `test_linalg_hessenberg`: existing real/complex reduction checks for the
  reused numerical dependency.

The existing `check_aaa.py` also passed 34 cases per build: 4,114 SciPy query
comparisons and 55 analytic spectral/residue values. Its maximum error/bound
ratio in both builds was `0.06751`. This checker accounts for support selection and
SVD differences between native AAA and SciPy.

## Direct pencil references

`check_aaa_spectrum.py` compares 41 normalized arrowhead pencils with SciPy's
independently compiled LAPACK. Support counts are 2, 16, 40, 41, 64, 100, 128,
200, and 512. Cases include real/complex coordinates and weights, tight complex
clusters, and cancellation of the leading secular coefficient. Comparisons
use homogeneous eigenvalues and the same explicit infinity threshold as the
public AAA implementation. Finite roots are paired by minimum-cost matching;
their counts must agree.

Analytic cases use unit-circle supports and weights proportional to
`1-0.4*s`. The secular numerator is proportional to `z**(m-1)-0.4`, giving
`m-1` simple, explicitly known roots. Together, the cases check 3,418 finite
SciPy eigenvalues and 1,094 analytic roots per build, including the 512-support
boundary and its two homogeneous infinite eigenvalues.

| Direct pencil comparison | Acceptance bound | Maximum in either build |
| --- | --- | --- |
| Matched `abs(native-reference)/(1+abs(reference))`, SciPy | `2e-8` | `4.27434e-14` |
| Same measure, analytic roots | `3e-10` | `6.34271e-15` |

The direct comparison validates the adaptation against a separately compiled
established implementation; the analytic cases provide an independent
mathematical reference. The full upstream LAPACK test suite was not run.
The wrapper supports a restricted pencil family and does not expose the
general LAPACK interfaces.

## Public larger-fit references

`check_aaa_large.py` exercises 24 public fits with 41, 65, 81, and 97 samples,
real nodes/data and complex nodes/data, and cleanup disabled, automatic, or
explicit with threshold 0.1. It retrieves each native retained representation
and independently builds its pole/zero pencils for SciPy. Thus spectral
comparisons assess the same rational function rather than requiring two
different SVD implementations to choose identical AAA supports.

Residue references use the independently computed poles and the differentiated
barycentric denominator. Pole ordering is matched before comparing residues.
In both builds, 23 representations remain above 39 supports; comparisons cover
3,336 poles/zeros and 1,668 residues. Cleanup removes 12 support points in
total, so the checks cover refitting rather than only no-op cleanup.

| Public comparison | Acceptance bound | Maximum in either build |
| --- | --- | --- |
| Matched normalized poles/zeros | `3e-8` | `7.54984e-15` |
| Residue `abs(native-reference)/(1+abs(reference))` | `3e-8` | `8.84251e-15` |

## Remaining limitations

The 512-support resource guard remains. Dense storage is quadratic and work
is cubic in the support count. The existing projective infinity threshold,
binary64 scaling limits, secular polishing tolerance, and simple-pole residue
assumption remain. Repeated or severely clustered poles and near degree
cancellation can still cause explicit numerical failure; a larger backend
does not cure an ill-conditioned rational representation. No C ABI is added.
