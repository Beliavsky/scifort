## Native checks

Create `build\fft-nd-native` before running these CMD commands:

```cmd
gfortran -O0 -g -fcheck=all -ffpe-trap=invalid,zero,overflow -fbacktrace -Werror=implicit-interface -Jbuild\fft-nd-native -Ibuild\fft-nd-native -Ibuild\gfortran_2806A042DAA8BBF7 src\fft.f90 test\test_fft_nd.f90 build\gfortran_3C159EB802C22FB9\scifort\libscifort.a -o build\fft-nd-native\test_fft_nd.exe
build\fft-nd-native\test_fft_nd.exe
```

The optimized command substitutes `-O3` for `-O0 -g` and
`fft-nd-optimized` for `fft-nd-native`, retaining the remaining checks.
FPM hashes are local artifacts; use matching paths from the local build.

Tests include an independent double DFT sum, normalization modes,
complex/real/Hermitian inverse pairs, all DCT/DST types, reordered/subset
axes, ranks 1/2/3/15, padding, strided input/output, input preservation,
empty input and batches, wrong output shapes, duplicate/out-of-range axes,
invalid lengths/options, DCT-I singleton rejection, and nonfinite values.
The intentional strided call emits array-temporary runtime warnings.

## External reference checks

```cmd
python validation\check_fft_nd.py --module-dir build\gfortran_2806A042DAA8BBF7 --library build\gfortran_3C159EB802C22FB9\scifort\libscifort.a
```

The checker compiles the changed FFT source and the input-driven driver
directly, using the archive for unchanged dependencies. The driver remains
outside `test/` and cannot block unattended FPM tests on keyboard input.

There are 9,298 reference cases: all ten multidimensional transform families,
real/complex overloads, rank-four shapes with singleton dimensions, axis
subsets and reordered axes, inferred axes from lengths, default/explicit
lengths, cropping/padding, all three normalizations, DCT/DST types I-IV,
default/explicit orthogonalization, empty inputs, and amplitudes
`1e-100` and `1e100`.

Reference build flags are `-O0 -g -fcheck=all
-ffpe-trap=invalid,zero,overflow -fbacktrace -Werror=implicit-interface`
and `-O3 -fcheck=bounds -Werror=implicit-interface`.
Scaled error is maximum complex absolute error divided by the larger of
maximum input magnitude, maximum reference magnitude, and minimum normal
binary64 value. The acceptance bound is `3e-12`, without a unit floor
that would conceal errors for small inputs.

For complex cosine/sine cases, the checker applies the public real SciPy
transform separately to real and imaginary components, preserving explicit
`orthogonalize`. This avoids the SciPy 1.15.3 complex-path option omission
documented in the [FFT guide](../docs/fft.md).

Both reference builds: all 9,298 cases passed; maximum scaled error
`5.989e-15` (real DST-II on reordered axes, with padding).
