# Boundary-value ODE solver validation, 2026-11-12

Compiler: GNU Fortran (GCC) **17.0.0 20260510 (experimental)** on Windows.
Reference environment: Python 3.13, SciPy **1.15.3**, NumPy.

## Native checks

`test/test_integrate_bvp.f90`: **53 assertions passed** in each of the
checked `-O0` and optimized `-O3` configurations below. Coverage includes:

- Coupled, nonseparated linear boundary conditions and exponential solutions.
- Analytic and estimated state, boundary, and unknown-parameter Jacobians.
- Both analytic Bratu branches, a normalized Sturm-Liouville eigenvalue,
  and an exponentially thin boundary layer requiring nonuniform refinement.
- Singular-endpoint Lane-Emden equations with analytic and estimated Jacobians.
- Holomorphic complex equations and an unknown complex parameter.
- Scalar/vector cubic output, derivatives through order four, unsorted queries,
  extrapolation, independent retained storage, and invalid evaluation arguments.
- Mesh-budget and singular-Jacobian exits; boundary-tolerance iteration limit
  with a deliberately inconsistent user Jacobian; nonfinite callbacks/Jacobians;
  invalid tolerances, budget, parameter, mesh, and initial state.

Bratu constants solve `8*a**2/cosh(a)**2=1`; both roots were independently
checked with SciPy's scalar bracketing solver rather than accepted from a
generated draft. The solution is `-2*log(cosh(a*(2*x-1))/cosh(a))`.

## Independent comparisons

`validation/check_bvp.py` with `validation/bvp_reference_driver.f90`:
**52 cases and 30,792 checked values passed per configuration**.
The cases vary equation coefficients, nonlinear branches, tolerance
(`1e-4`, `1e-7`), thin-layer scale up to 1000, real/complex state, two unknown
real parameters, and real/complex singular endpoint terms. Values and first
and second dense derivatives are checked at 81 coordinates. Available
analytic solutions independently check the mesh solver, rather than relying
only on the closely related SciPy algorithm.

49 cases compare successfully with converged SciPy solutions. In three
complex Lane-Emden reference cases, SciPy 1.15.3 exceeds 3000 nodes, including
when supplied exact analytic Jacobians. The SciFort results converge and are
checked against the entire analytic solution `sin(q*x)/(q*x)` and its first
three derivatives. The script explicitly reports these reference failures:

| Complex `q` | Requested tolerance | SciPy reference result |
| --- | --- | --- |
| `3*(1+0.3i)` | `1e-4` | Mesh budget exceeded |
| `1+0.3i` | `1e-7` | Mesh budget exceeded |
| `3*(1+0.3i)` | `1e-7` | Mesh budget exceeded |

For the comparison of derivative order `d=0,1,2`, error is normalized by
`1+abs(reference)` and bounded by `tol`, `tol**0.75`, and `tol**0.5`,
respectively. This accounts for differentiation of the cubic interpolant and
different adaptive meshes. Maximum observed error divided by those bounds:
approximately **0.01121, 0.04412, 0.19811**, respectively, in both builds.
Unknown parameters use absolute and relative tolerances of `10*tol`.
Analytic solution checks use `5*tol` absolute and relative tolerances, with
the coupled linear problem scaled by the square root of its endpoint-matrix
condition number. That example deliberately demonstrates that a local defect
bound need not imply the same global solution error in ill-conditioned BVPs.

## Practical limits

This validates the listed cases, not arbitrary stiffness, conditioning, or
complex BVPs. The native sparse LU uses row pivoting without column reordering;
large or highly ill-conditioned systems may need a specialized backend.
Numerical arithmetic must remain in the binary64 range. Iteration counts and
meshes need not reproduce SciPy's frozen-Jacobian implementation. No C ABI
or wrapper was added. See the [API guide](../docs/bvp.md) and
[provenance record](../CODE_PROVENANCE.md).
